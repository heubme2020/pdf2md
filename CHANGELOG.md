# Changelog

## v18 — 2026-10-16: UK ESEF layout-aware rebuild + Brazil + Korea EUC-KR raw bytes + English reports

Four independent fixes bundled with the held v17 (UK shell-strip / SEC 20-F) into one release, per the "攒齐再发" rule.

### What changed

1. **UK ESEF layout-aware rebuild** (`unified_convert`)
   The v17 shell-strip still treated all ESEF XHTML as flat text, so headings/tables in the three real UK formats were lost. Rebuilt with format-aware parsing:
   - `_uk_to_md` dispatcher: ZIP bundle (Workiva multi-XHTML) vs single-file XHTML (DirectUpload / AIM).
   - `_uk_font_map`: extract the CSS `fs`→size map from `<style>` *before* dropping `<head>`.
   - Three heading detectors by generator: `_uk_divs_to_md` (pdf2htmlEX absolute-positioning `div`s, `fs`/`ff`/`y`), `_uk_strong_to_md` (bold markers), `_uk_class_to_md` (Workiva CSS classes).
   - Full `html.unescape` replaces the hand-written 6-entity map (`&#8217;`, `&#233;`, `&#57535;` … no longer leak as raw entities).

2. **Brazil `br_xml_to_md`** (`unified_convert`)
   New market converter wired into `convert_data`'s `br` branch.

3. **Korea DART EUC-KR raw-byte preservation** (`dart_fetch`)
   - `fetch_document_xml_raw`: archive the *raw bytes* instead of decoding at download time. v16's `_decode_dart_xml` handles CP949 decode correctly at convert time, but only if the original bytes weren't already destroyed to U+FFFD — the 9k empty `ksc` shells' root cause.
   - `classify_disclosure`: reject `[첨부정정]`/`[정정]` correction announcements (DART has no `document.xml` for them → `014` response → empty shell).

4. **English report headings & tables** (`pdf_to_md`)
   - Bold-font heading detection: `"Bold" in font` now triggers a heading (Sri Lanka etc.).
   - `_detect_tables_en`: boxed + line detection only, text method disabled — the text heuristic was slicing multi-column English prose into 6-column fragments (Royal Ceramics), yielding zero headings and run-on digits.

5. **Metrics B6 dedup + D6 audit question** (`pdf2md_metrics`)
   B6 duplicate false-positives filtered out of the table rows; D6 version-spot-check added to the 31-question audit.

## v17 — 2026-10-13/14: UK ESEF metadata-shell strip + SEC 20-F Broadridge headings & whitespace

Two independent fixes folded into one release (v17 was held before push, per the "攒齐再发" rule).

### What changed

1. **UK ESEF XBRL metadata-shell stripping** (`unified_convert._uk_esef_to_md`)
   ESEF iXBRL wraps the whole document in `<ix:header>`/`<ix:hidden>` carrying LEI codes, period dates, and `ifrs-full:*Member` dimension members — 1.36M chars of noise before the actual text. Fix: strip both shells outright. UK reports drop 1.36M → ~90k chars.

2. **US SEC 20-F section headings — Broadridge anchors** (`edinet_html._TextWalker`)
   Newer foreign-private-issuer 20-Fs (China ADRs like Ascentage Pharma AAPG) are generated by **Broadridge Transform**, which marks each section with an empty `<a id="a_003">` anchor — no `<h1>`–`<h6>`, no `<div id>`. The old walker only knew those two carriers, so Broadridge 20-Fs came out with **zero headings** (worker `get_section`/`list_sections` returned empty). Fix: recognize `<a id>`/`<a name>` anchors, emit `## <toc title>`, and skip the bold body heading that follows (avoid duplication; financial-statement titles span multiple `<p><b>` blocks).

3. **US SEC TOC long-title dropping** (`edinet_html._toc_titles`)
   The `len(text) <= 40` guard meant to skip page numbers also dropped long `ITEM` titles ("ITEM 14. MATERIAL MODIFICATIONS TO THE RIGHTS OF SECURITY HOLDERS AND USE OF PROCEEDS" ~82 chars) — the whole section lost its heading. Raised to 200; pure-digit page numbers are already filtered by `isdigit()`.

4. **US SEC word-per-line / run-on text** (`edinet_html._TextWalker`)
   Broadridge puts a literal `\n` between words in its cover ("UNITED\nSTATES\nSECURITIES…") and `<p>`/`<div>` never flushed, so the whole narrative came out as one run-on blob. Fix: collapse `\s+` → single space in `handle_data` (leaving `<br>`'s real newline), and flush on `<p>`/`<div>`/`<li>` block boundaries. Also fixes the Workiva "UNITED STATESSECURITIES" missing-space concat.

### Verification

Four SEC generators sampled before/after (`##` count, duplication, readability):

| Generator | Example | headings before → after |
|---|---|---|
| Broadridge | AAPG (Ascentage) | 0 → **42** (all ITEM 1–19 + PART I/II/III + financial statements) |
| Workiva | TIGO, MUFG, ASML | 53 → 66 (long titles un-dropped) |
| Donnelley | BABA | 7 (`h1`) → 7 (unchanged) |
| h4/h5-type | SOHU | 0 → 161 (`h5`) |

Japan (EDINET) and Taiwan (MOPS) spot-checked: heading hierarchy and tables intact, no regression.

## v16 — 2026-10-13: Korea EUC-KR decode + SEC `$`/headings + A-share containment dedup

A full-market data-quality audit (31 checks × 7 stocks per exchange) surfaced a batch of converter bugs, fixed at the root:

### What changed

1. **Korea DART legacy-report garbling** (`dart_fetch._decode_dart_xml` + `unified_convert`)
   DART's `document.xml` always declares `encoding="utf-8"`, but legacy reports (e.g. 2006) are actually **EUC-KR**. Decoding as UTF-8 produced ~59,000 U+FFFD replacement chars (all Hangul lost). Fix: a "whichever decode yields fewer U+FFFD" self-check — fall back to cp949 when UTF-8 floods the output with replacement chars. Legacy reports drop from ~59,000 U+FFFD to 0; new reports (genuine UTF-8) are unaffected.

2. **US SEC `$`-in-its-own-cell column misalignment** (`edinet_html._merge_signs`)
   Workiva puts `$` in its own `<td>` and the number in the next cell. The old merge collapsed them into one cell, shifting `$`-rows one column left and breaking `table_footing` (AAPL "Cash" 2024 value landed one column off). Fix: merge `$value` back into the `$` cell (the header's start column) and blank the number cell — column count preserved.

3. **US SEC heading degradation (`PartI/1/13`)** (`edinet_html._toc_titles`)
   SEC TOCs have three links per anchor (`Item 1.` → `Business` → page `1`). The old `out[anchor]=text` last-write-wins grabbed the page number, and `re.sub(r"\s+","")` turned "Part I" into "PartI". Fix: skip pure-digit page numbers, first-write-wins, collapse (not strip) whitespace — zero impact on Taiwan (single link, no intra-word spaces).

4. **US OTC no-section fallback** (`convert_local._sec_toc_fallback`)
   OTC/small-cap filings have no `<a href>` TOC (the TOC is a `<table>`), so zero headings were extracted. Fallback: recognize `Item N.` / `PART I/II/III/IV` rows in the emitted TOC table and emit `##` headings.

5. **A-share cross-page table duplication** (`pdf_to_md._detect_tables`)
   The text strategy split one table into "one wide table + several 2-column fragments"; fragments were too small to hit the 50%-overlap threshold, so all were kept, repeating headers. Fix: `_bbox_contains` "fully-contained + fewer columns" dedup.

6. **Metrics fixes** (`pdf2md_metrics`)
   `duplication` no longer counts Markdown `|---|` separator rows as repeated content; `_TOTAL_RE` now matches `total` with word boundaries (no more "Dow Jones … Total Stock Market Index" false hits).

## v15 — 2026-10-11: A-share table dedup fix + FMP 3-statement truth

### What changed

1. **A-share three-line table dedup fix** (`pdf_to_md._detect_tables`)
   `find_tables(strategy="lines")` over-splits A-share three-line tables (horizontal rules only) into 9 columns and truncates wrapped labels ("…的影响" split off). The merge now prefers the handwritten line detector when the boxed table has **>2 more columns** than it (over-split), while still preferring `find_tables(lines)` for HuaKang boxed tables (Japan/Taiwan, where the handwritten detector smears text).

2. **Generic cross-page table merge** (`pdf_to_md.convert`)
   A table block ending at the page bottom and continuing at the next page top (same column count) is merged into one table instead of two fragments.

3. **FMP truth extended to all three statements** (`fmp_source`)
   Adds income-statement (`revenue`/`operatingIncome`/`incomeBeforeTax`/`netIncome`) and cash-flow (`operatingCashFlow`/`netCashProvidedByInvestingActivities`/`netCashProvidedByFinancingActivities`) fields, with a `FIELD_STATEMENT` mapping to pick each field from its own statement. `labeled_facts` now reads all three statements.

### Verification

Frozen test set (52 A-share reports, `_cashflow_eval.py`), cash-flow **C1 identity** (期末 = 期初 + 经营 + 投资 + 筹资 + 汇率): **51.6% → 71.1%**. Japan FMP pairing unchanged (60% before = after), confirming no regression on the iXBRL path.

## v14 — 2026-10-07: UK ESEF (new market)

The UK files annual reports in **ESEF iXBRL** — an XHTML wrapper whose layout is a PDF-style text layer (no `<h1>`/`<table>`, text placed by x/y coordinates + font size). v14 adds a structured converter for it.

- `_uk_esef_to_md` (`unified_convert.py`): `<table>` → Markdown tables, everything else → paragraphs, `ix:` tags stripped, `<body>` only.
- Replaces the v13 "one line per `</div>`" flat dump (0 tables + `<style>` CSS leakage) with structured tables + paragraphs.
- Numbers stay verbatim (no OCR, no rewrite).

## v13 — 2026-10-07: frameless balance-sheet extraction

The big fix for the biggest failure mode: Japan/Taiwan balance sheets use **whitespace column alignment instead of ruled lines**, so the old line-based detector couldn't find the totals at all — A1 accounting identity passed on only **2%** of Japan/Taiwan reports.

### What changed

1. **Frameless balance-sheet line parser** (`pdf_to_md._parse_balance_sheet`)
   Parses `科目代码 + 科目名 + 金额` line-by-line instead of relying on table detection. Pre-scans the balance sheet across pages and replaces the fragmented `find_tables(text)` output with a clean grid.

2. **Boxed-table detection merged in** (`pdf_to_md._detect_tables_boxed`)
   `find_tables(strategy="lines")` handles boxed tables (fund-lending / endorsement / schedules) that the handwritten detector smeared into one blob — the root cause of the TSMC garbling. Merged + deduplicated with the handwritten line detector (boxed wins on overlap).

3. **Hardened total-row extraction** (`pdf_to_md._find_total`)
   - Label matching switched from anchored `^…$` to `search` + CJK negative-lookbehind (`(?<![一-龥])`) — matches labels on the same line as an account code (`0.77 2xxx 負債總計`) while still excluding subtotals (`流動負債合計`) and the grand total (`負債及權益總計`).
   - Account-code fallback (`1xxx`/`2xxx`/`3xxx`) recovers a total when `get_text()` separates the label from its amount by >100 lines.

### Verification

Full benchmark (127 reports/market, sampled from a full archive; results in `bench_quality_v13.json`):

| Market | A1 pass rate (v12 → v13) |
|---|---|
| A-share | 62.2% (three-line tables, unaffected; sample variance) |
| **Japan** | **2% → 86.6%** |
| Taiwan | 2% → 10.2% (whole archive: 47/127 HuaKang-garbled + mostly quarterly reports) |

On the curated Taiwan annual-report set, A1 self-consistency is **87% → 98%** (47/48; the one failure is a HuaKang-font garbled page, not a parsing bug).

### Known limits

- `2637` (TW) uses letter-form account codes (`11XX` / `2XXX`) inline with labels — a non-standard format the line parser still skips (no longer emits *wrong* data, just doesn't extract it).
- HuaKang-font garbled pages (`DFKaiShu` "Estd-BF" private glyph IDs) are a font-level problem, out of scope for the parser.

## v12 — 2026-10-02: three-line table row split, fake-heading fix

1. **Three-line table row boundaries without horizontal rules** (`table_detect._row_boundaries`)
   Japan income statements have no ruled line between consecutive items (only before subtotals). The old rule-based row split glued items together; the new word-y-gap split recovers them. Main source of Japan value-recall +2.2pp.

2. **Fake-heading font-size check** (`pdf_to_md` h3, `size ≥ 12`)
   A-share headings and body text are the same typeface, distinguished only by font size. The old regex+length check mislabeled body sentences as headings; size check fixes it.

3. **SEC `$` sign merge** (`edinet_html._merge_signs`)
   US iXBRL (Workiva) puts the `$` in its own `<td>` and the number in the next — the old split produced two columns and failed value matching.

4. **Unified section ontology** (`section_ontology.py` + `gen_focus_points.py`)
   One cross-market concept set (mda / financial_statements / notes / audit_report …) with a per-market heading mapping.

5. **Evaluation four filters** (`fmp_eval.py`)
   Archive garbage / FMP self-consistency / restatement cliff (Q3→Q4 jump) / label scope — strips ground-truth noise from parser quality.
